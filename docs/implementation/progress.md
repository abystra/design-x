## 明确的实施取舍

1. 前端保留 `src/` 及现有CSS，新增 `apps/web` 工作区入口；文档核心和新后端为严格TS，旧UI按allowJs渐进迁移。当前继续使用hash路由，真实project ID进入地址；路由库迁移不作为真实链路运行前置。
2. 认证用邮箱密码+scrypt和服务端会话，没有把未接通的短信/邮件服务作为登录能力。会话Cookie HttpOnly，生产Secure；会话令牌只存哈希。
3. HTTP按 `/api` + camelCase 适配原型；文档形状兼容原型且经共享Zod校验。服务端持久化Board、Artboard、版本、ops/inverse，409显式冲突；未实现自动rebase。
4. 使用评审入库SQL迁移；pg事务显式设置租户角色和RLS。Drizzle连接已提供，未虚称所有SQL由Drizzle生成。
5. Board沿用原型DOM路线，保留用户熟悉的布局，未引入tldraw依赖或许可。便签、扁平分区与显式成员已完成专项验证；移动成员不自动改变归属，分区无嵌套。空间虚拟化和规模性能仍待深化。
6. 文档文字统一使用随依赖打包的 Noto Sans SC Variable / Source Serif 4 Variable，代替机器相关字体。页面外壳视觉保留；设计字体的差异用于跨环境一致渲染。编辑、Board预览、导出共用NodeContent。
7. `.dxproj` 为自包含JSON v1（Board、Artboards、素材数据），已提供真实导出与跨账户导入；未知版本拒绝。导入是独立Worker任务，新项目/文档/资产/引用与成功状态同事务提交，S3暂存通过manifest补偿。源文件40MiB、素材解码后合计30MiB，失败源包保留供重试，长期清理未实现。上传使用受认证API流式接收后存S3，尚非浏览器预签名直传。
8. 原型规则仅为测试夹具。AI按钮明确未接入，不再产生计时器“成功”结果。
9. 软删保留文件以支持版本恢复；定时GC/硬删除、账户邮件找回、多人协作、批量SKU、多页/视频仍单列，不能标为完成。
