## 建议实现契约（实现落定后核对）

以下为验收建议。Board 共享 schema 已落地的字段和导入 API 拟定契约见下一节，其余交互行为仍待前端实现及验证。

1. 便签有稳定 ID、正文、颜色、位置和尺寸；分区有稳定 ID、标题、颜色、位置、尺寸和显式成员关系。缺失新增数组的旧 Board 可按空数组加载。值应有明确类型、长度/数量/坐标范围，重复 ID 和悬空引用不能进入数据库。
2. 先定义分区是否允许嵌套、成员能否属于多个分区。建议本轮采用扁平分区和单一归属，避免循环；若采用不同语义，测试必须随实现契约调整，不能仅靠视觉包含关系猜测成员。
3. 移动分区时成员平移相同 Board 坐标差值；同时选择分区与成员时每个对象只移动一次。删除分区默认保留内容，删除成员移除相应成员引用。复制选区需要重建复制对象之间的成员映射，不能把新分区指向原来的成员。
4. Board 本地撤销/重做覆盖便签、分区和成员关系；一项交互按一项历史操作恢复。恢复组织快照不得用旧的 `result.design` 覆盖独立 Artboard 的最新正文。发生 409 时保留本地内容并停止静默覆盖，采用现有明确的冲突处理入口。
5. 导入创建当前用户空间中的新项目、Board、Artboards 和私有资产；不能复用来源空间的 project/document/asset ID，也不能直接保留来源私有 URL。图层 ID 可以保持文档内稳定，前提是仍满足唯一性与组关系约束。
6. 原生导入需要保持画板顺序、Board 位置、便签正文/颜色/尺寸、分区成员关系、图片裁切和其他设计内容。导入后的主画板与 Board 引用指向新文档；导入是新项目的起始状态，不伪造原账户历史版本、任务、会话或权限。
7. 对每个被携带的私有素材引用验证存在匹配的内嵌文件，解码并验证实际图片，存入当前空间的新对象键，再统一重写引用。只给 URL、没有文件数据的私有引用不能通过。无需为了读取包内容访问来源账户 API 或任意外部 URL。
8. 导入响应成功前必须满足数据库关系完整性。数据库写入需在事务中完成；对象存储写入与数据库不能冒充一个跨系统事务，失败时应有明确的补偿清理与错误记录。请求重试行为要明确，避免双击或网络重试制造不知情的重复项目。

## 当前实现进展与拟定接口

已只读核对 [Board schema](../../packages/doc-core/src/board.ts)：`notes`、`sections` 默认空数组；便签字段为 `id/text/position/width/height/color`，分区字段为 `id/title/position/width/height/color/itemIds`。分区不允许嵌套，成员只能是现有 Artboard 或便签；一个成员只能属于一个分区，所有条目 ID 唯一。Artboard 正文仍由独立 documents 行提供。

实施者报告新增 [Board 单测](../../tests/unit/board.test.ts) **3/3**、[真实 Board API 测试](../../apps/api/tests/board.integration.test.ts) **4/4** 通过，全部单测合计 **10/10**。验收者已阅读用例，未另行重跑。覆盖旧 Board 默认值、成员/重复 ID/坐标校验、真实保存重开、无效写入及 409 不改变数据、跨账户 404、删除分区保留成员与 inverse 记录、无效新画板位置不创建数据。这些结果不能替代前端拖动、混合复制或浏览器导入验收。

导入实施方提供的拟定契约如下，**尚待最终代码和执行结果确认**：

- `POST /api/projects/import`，multipart `file` 字段，上传 `.dxproj` JSON；返回 `202` 和 `project.import` 任务 DTO。成功任务的 `result.projectId` 指向新项目，HTTP 202 本身不等于导入成功。
- 源文件上限 40 MiB；拟定上限为 100 个 Artboard、200 个素材、总计 10,000 个图层；每图 10 MiB / 40 MP、总计 100 MP。实际解码在 Worker 进行。
- 结构/版本/引用闭包错误拟返回 422，文件过大返回 413；解码、对象存储或写入失败若发生在接收任务之后，应在任务失败终态中反馈。同步拒绝和异步失败的准确分类待实现核对。
- Worker 创建新私有 S3 文件，并在同一数据库事务中创建项目、文档、资产和引用，同时完成任务状态；重映射文档、图层/组合、便签、分区和成员，以及私有 URL/支持的 Board 引用。
- 新导出将收集 Board 素材并提供 `primaryArtboardId`。有效且完整的旧 v1 文件计划兼容；旧文件若缺少 Board 单独引用的私有素材，将明确拒绝，不借用来源账户权限补图。

## 关键风险与建议测试

### Board 组织与编辑

| 编号 | 风险 | 建议验证方式 |
|---|---|---|
| B01 | 旧 Board 因新增必填字段无法打开 | 用本轮前创建的真实项目打开/保存/重开；空 notes/sections 的兼容性单测 |
| B02 | 相同 ID 被多个类型占用或分区成员不存在 | 共享 schema 单测与真实 API 拒绝用例；确认数据库 revision/content 未变 |
| B03 | 同时选中分区和成员，成员被移动两次 | 用两个 Artboard 和一个便签建分区，混合选择拖动；比较服务端每个 frame 的差值，而非仅截图 |
| B04 | 删除/复制后产生悬空成员或引用原成员 | 删除分区后内容仍在；删除成员清理关系；混合复制后 ID 唯一且成员映射到副本；逐步撤销/重做精确比较 |
| B05 | 组织历史覆盖精细编辑器的新正文 | Board 组织操作后进入 Artboard 编辑保存，再返回撤销组织操作；正文保持最新，位置/成员按历史变化 |
| B06 | 文本输入触发删除、全选或画布快捷键 | 在便签正文/分区标题中编辑、换行、Backspace；焦点仍在输入框。真实中文输入法另做人工验证，不用 `fill()` 代替 |
| B07 | 保存中切换页面、刷新或 409 丢失数据 | 保存成功后刷新/重登并读取真实 snapshot；两个标签对同一 Board 保存，第二次 409 不修改服务端，不清空本地输入 |
| B08 | 屏幕坐标与 Board 坐标混淆 | 至少在 50% 与 150% 缩放下移动/调尺寸，核对文档坐标；fit 能包含便签与分区；缩放本身不改内容 |

### `.dxproj` 真实导出与跨账户导入

| 编号 | 风险 | 建议验证方式 |
|---|---|---|
| I01 | 仅能导入手写夹具，不能导入产品自身文件 | 账户 A 在 UI 创建真实内容并上传图片，真实 Renderer 导出、浏览器下载，再由账户 B 的文件选择器导入该文件 |
| I02 | 新资产仍引用 A 的 ID/对象/权限 | 比较导入前后 asset ID 与 URL；B 能读新 file/thumbnail，A 和未登录访问返回 404/401；B 不能读 A 原资产 |
| I03 | 只重写 Artboard 节点，Board 元数据仍留旧私有 URL | 检查所有实际支持的 Board 字段（例如 assets、attached、reference、结果预览）和文档节点；测试仅在 Board 引用的素材。对不携带字段明确清理规则 |
| I04 | 缺图、损坏数据或伪造 MIME 也创建半成品 | 缺失 assets 条目、损坏 base64、声明 MIME 与实际图片不符、超限文件，均得到明确 4xx；项目/文档/引用数量不增加 |
| I05 | 伪造路径或来源触发任意读取 | 未打包的 `/api/assets/...`、远程 URL、路径穿越、未知 data MIME 不被下载或读取；只接收已定义的原生格式 |
| I06 | 文档图关系不完整 | 重复文档 ID、未知 kind/version、多个或缺少 Board、悬空 Artboard/分区成员/主画板引用，按明确兼容规则拒绝且无局部写入 |
| I07 | DB 错误后留下可见项目或可读半成品 | 真实集成测试注入事务失败，确认项目/文档/asset_refs 回滚；验证已写 S3 对象补偿路径。单纯 schema 拒绝不能证明写入中途回滚 |
| I08 | 网络重试产生重复导入 | 按最终幂等契约重发同一请求，核对项目/资产数量；若导入每次有意新建，UI 应防重复提交并清楚反馈结果 |
| I09 | 导入能预览却不能继续编辑/导出 | B 刷新、重登、编辑其中一个 Artboard、保存，再导出 PNG 和 `.dxproj`；内容来自新项目和新素材 |
| I10 | 原文件来源被删除后导入副本失效 | A 软删来源项目后，B 仍可读取自己的素材并渲染/导出；导入副本不依赖 A 会话或项目的生命周期 |

包级大小、单素材解码大小、总解码字节数、文档/节点/便签/分区数量上限需要分别验证。JSON 中 base64 体积不等于解码后的图片成本；HTTP body limit 与导入 API 限制也必须一致，错误不能只表现为前端无响应。
