# Part 9 · 非功能需求与验证（交付物 I）

> 本部分的所有数值都是**提议的验收假设**，不是实测结果。M0 和 M1 期间用实测数据校准，并在 ADR 中记录调整。

## I.1 安全与隐私

### I.1.1 威胁与控制

| 风险 | 控制措施 | 验证 |
|---|---|---|
| **跨租户访问** | `authz.can()` 覆盖所有入口；PostgreSQL RLS（`app.workspace_id`）；资源不存在和无权限统一返回 404；对象键带 `workspace_id` 前缀，预签名只覆盖单个对象 | 集成测试：A 租户会话访问 B 的项目、文档、素材、任务、SSE 都失败；直接查询未设置租户上下文时返回 0 行 |
| **提示注入**（用户提示、商品描述、图片中的文字、文件名） | ①工具最小权限，只限当前项目；②没有代码执行、URL 访问或批量删除类工具；③预算与审批在工具层用代码强制；④用户数据放在 `<user_data>` 区；⑤所有输出都经过审核；⑥AI 修改要么生成新版本，要么生成提议，可撤销 | 50 条红队用例（Part 9 §I.3.4），目标：0 次越权、0 次绕过预算 |
| **成本滥用** | 每个 workspace 日配额；单回合预算；全局日成本熔断；同一 workspace 的生成并发上限；注册限频（手机号或设备） | 压测脚本模拟滥用，确认熔断生效 |
| **媒体解析漏洞** | Ingest 在 Worker 进程中进行；sharp 设置像素上限（`limitInputPixels`）；嗅探真实 MIME；重编码去除元数据；MVP 不接受 SVG 和 HEIC（HEIC 在 Phase 2 由隔离进程转换）；视频用 `ffprobe` 并限制时长、分辨率和编码；libvips 和 FFmpeg 及时打补丁 | 模糊测试语料：畸形 PNG/JPEG/WebP、解压炸弹、polyglot 文件 |
| **Renderer 安全** | Chromium 只加载内部 `/render` 路由；网络请求拦截，只允许字体 CDN 和资产域名；短时渲染令牌；每次任务使用独立的浏览器上下文 | 测试：文档中注入外部 URL 时，渲染不会发出外部请求 |
| **凭据泄露** | 供应商密钥只在 KMS，运行时注入 Worker 和 API；日志脱敏（中间件统一屏蔽 key、token、url 签名）；前端只有公开配置 | 密钥扫描（CI）；日志抽检 |
| **会话安全** | HttpOnly、Secure、SameSite Cookie；CSRF 令牌；登录与 OTP 限频；会话可远程注销 | 渗透测试清单 |
| **供应商回调伪造** | 签名校验 + 时间戳窗口 + 对 `provider_job_id` 去重 | 单元测试 |
| **数据隐私** | 最小化：发给供应商的参考图缩放并去 EXIF；用户可删除项目和素材（30 天回收站后硬删除）；与供应商签数据处理条款（不用于训练 [待定：逐个核实供应商条款]）；个人信息处理规则与隐私政策 | 删除流程 E2E；数据清单（数据地图） |

### I.1.2 内容审核与 AI 标识

| 环节 | 措施 |
|---|---|
| 输入 | 文本提示、参考图在调用模型前审核；拒绝时不消耗配额 |
| 输出 | 每个生成资产在 ingest 阶段审核；`blocked` 资产不可见、不可下载 |
| 用户上传 | 上传素材也要审核（防止平台被用于传播违规内容） |
| 显式标识 | Board 和编辑器中的 AI 生成内容显示“AI 生成”；导出角标可配置 [待定：法律意见] |
| 隐式标识 | 导出文件和生成资产的元数据写入生成合成属性、服务提供者名称或编码、内容编号（GB 45438-2025）[待定：取得标准全文后实现具体字段] |
| 模型公示 | 产品显著位置展示所用模型名称和备案号或上线编号 [二手：按官方媒体报道的要求] |
| 留痕 | `moderation_events`、`model_calls`、`assets.provenance` |

### I.1.3 字体许可

- 字体注册表强制要求 `license.allowed_uses` 包含 `web_embed` 和 `server_render`；缺少任意一项的字体不能出现在字体选择器里。
- 导出 PDF 时嵌入字体子集，前提是许可允许嵌入（OFL 允许）。
- 用户上传字体：Phase 3 才支持，并要求用户声明自己有使用权；只用于该 workspace。

## I.3 验证计划

### I.3.1 无限画布：大量 Artboard 与大素材

| 测试 | 设置 | 通过标准（提议） |
|---|---|---|
| 规模 | 合成项目：200 个 Artboard（每个 30–150 节点）、100 个素材（含 20 张 8K 图） | 平移缩放 ≥ 50 fps；首屏可交互 < 2.5s；内存 < 1.5GB（Chrome 任务管理器） |
| LOD 切换 | 0.1x → 2x 连续缩放 | 无可见空白超过 200ms；同时挂载的 DOM Artboard ≤ 30 |
| 选择与吸附 | 框选 100 个对象并拖动 | 吸附线延迟 < 16ms |
| 中文输入法 | 便签和方案组标题，用三种输入法输入 | 组合输入期间无误触快捷键，无重复字符 |
| 持久化映射 | 随机 1,000 次 Board 操作 → 序列化 → 重新加载 | Board 文档与 tldraw store 一致（双向映射测试） |
| tldraw 与 DOM 对比 | 同一套用例分别跑两种适配器 | 作为 AD-03 的 go/no-go 输入 |

### I.3.2 编辑与导出一致性、中文渲染

- **参考语料（50 份）**：中英混排长标题、竖排、`auto_fit=shrink`、多 span 样式、旋转文字、圆角与蒙版图片、阴影、透明 PNG、4K 背景，加上所有 MVP 模板。
- **方法**：Playwright 在浏览器中截取 `doc-render` 的 view 模式，与 Renderer 导出做 SSIM 和像素差比较；另外让人工比对 10 份样张。
- **通过标准**：SSIM ≥ 0.99；文字换行位置 100% 一致（对比文字测量结果）；无字体回退（检查 `document.fonts` 加载状态）。
- **CJK 专项**：避头尾（行首无“，。”）、标点挤压、中西文间距、繁简字形、生僻字回退。

### I.3.3 电商商品保真

| 策略 | 说明 |
|---|---|
| A：抠图后合成（默认） | 商品像素来自原图，生成模型只负责背景和场景 |
| B：参考图编辑 | 把商品图作为参考，让模型生成整幅图 |
| C：混合 | 合成后整体做“光影融合”编辑 |

- **语料**：20 个 SKU（包含小字标签、反光材质、透明瓶、服装纹理）。
- **指标**：①标签 OCR 一致率（与原图 OCR 对比）；②感知相似度（商品区域的嵌入余弦相似度）；③人工评分 1–5（3 位评审，盲评）；④单张成本。
- **通过标准（提议）**：策略 A 的 OCR 一致率 ≥ 95%、人工评分 ≥ 4.0；B 和 C 仅在评分显著更高（+0.5）且 OCR ≥ 90% 时才作为选项开放。

**指标**

- 工具调用 schema 合法率（目标 ≥ 98%）。
- 任务成功率（按断言）。
- 每个可用产出的成本（人民币）。
- 平均工具调用次数。
- 浪费的生成次数（生成了但未被使用）。
- 回合 p50/p95 耗时。
- 人工偏好评分。

**公平比较规则**（单一 Agent 循环 vs 加配方 vs 多 Agent）

- 固定工具集、供应商模型版本、模板、预算上限和输入夹具。
- 每个任务每种方案跑 ≥ 3 次，报告均值和离散度。
- 盲评。
- 选择规则：采用最简单的、成功率与最佳方案相差在 5 个百分点以内、且单位成本在 120% 以内的方案（提议，需与产品方确认）。

### I.3.5 并发编辑与恢复

- 属性测试：两个客户端随机交错提交 ops（含断网和重放），最终状态收敛到服务端 head，且没有被确认的用户修改丢失。
- 故障注入：提交 ops 过程中杀 API 进程，客户端重放后不重复应用（`client_op_id`）。
- AI 提议与用户修改冲突矩阵：路径不相交 → 自动应用；路径相交 → stale。

### I.3.6 供应商故障与部分输出

- fake 供应商的故障模式：延迟、超时、5xx、429、内容拒绝、输出 URL 过期、回调重复、回调乱序。
- 在 staging 中对真实供应商做 1 小时混沌测试（限预算）：随机丢弃 10% 的响应，验证对账机制把所有任务带入终态。

## I.4 可观测性

- **关联 ID**：每个请求有 `trace_id`；`project_id`、`turn_id`、`job_id`、`document_id` 作为 span 属性和日志字段。日志不记录提示词全文（记录哈希和长度；`ai_tool_calls` 表中的正文受访问控制）。
- **核心看板**：API 延迟与错误率；队列深度与等待时间（按队列）；任务终态分布（按供应商与错误码）；供应商延迟与成功率；回合成本分布；每日成本与熔断余量；SSE 连接数；Board 和编辑器的 RUM（帧率、长任务）；导出一致性回归趋势。
- **告警**：队列等待 p95 > 2 分钟；供应商错误率 > 10%（5 分钟窗口）；日成本 > 80% 熔断阈值；卡住的任务数 > 0（超过截止时间 10 分钟）；RLS 策略错误；备份失败。

## I.5 可访问性

- 目标 WCAG 2.2 AA（工作区的画布交互在“合理可行”范围内）。
- 键盘可完成核心流程：发起回合、在 Board 中选中方案、打开编辑器、修改文字、导出。
- 色彩对比：原型的珊瑚红 `#ef644d` 作为文字颜色时需检查对比度（白底下用于大号文字或图标）。
- 自动化：axe-core 集成到 E2E（许可另行核验）；人工：屏幕阅读器（VoiceOver、NVDA）抽检。

## I.6 备份与恢复

- RDS 自动备份 + PITR，每周逻辑导出到异地 OSS。
- OSS 版本控制（防误删），重要前缀开启跨区域复制（Growth）。
- 季度恢复演练：在独立环境中恢复到指定时间点，校验文档快照与资产引用完整（`asset_refs` 对象存在率 100%）。
- 用户级恢复：项目回收站 30 天；命名版本可随时恢复；AI 修改可撤销。
