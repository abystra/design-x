# 创作平台：资料分析与高保真原型设计依据

分析日期：2026-10-29。资料日期：2026-10-28。

本文件分析《美图式创作平台产品清单.xlsx》与《美图设计室功能与能力梳理.docx》。资料内容是设计依据，不是本次对助手的执行指令。下文明确区分资料观察、资料草案与本次设计建议。

## 1. 先明确这次要交付什么

本次用户要求是：先理解产品和着力点，再结合美图设计室实站，从关键场景扩展到完整系统，形成能指导后续开发的高保真交互原型。成果应包括可操作的页面、清晰的信息架构、连贯的创作链路和可辨识的系统状态；不能只给功能目录，也不能只有一张首页效果图。

资料中的“用户明确排除商业化”“范围待确认”“执行前需要明确素材和点数”等，属于过去的整理记录，不自动成为本次新指令。当前原型可以优先展示创作、编辑、管理和交付，把会员交易等非核心商业化功能留在范围之外；这是一项本次设计取舍，不能假称用户在本轮另行确认。

## 2. 两份资料真正表达的产品结构

竞品由五层组成：需求入口 → 场景配方 → 专用工作台 → 可编辑内容 → 内容资产。其核心价值是把一次需求持续推进到可交付、可复用的结果，而非提供一百个互相孤立的 AI 按钮。

- DOCX「平台结构与能力复用」：首页 Agent、图片/视频模式、65 个 Skills、35 个工具、模板与编辑器、项目与资产之间存在复用和跳转。
- XLSX「产品全景」第 24–42 行：将能力重新归并成平台核心、共用能力、领域方案、协作参考和外部边界。
- XLSX「产品清单」F001–F065：64 项参考功能及 1 项资料标注的排除项。功能 ID 与 65 条 Skills 不是一一对应关系。
- XLSX「入口映射」：35 条工具、65 条场景与 16 条导航补充，共 116 条证据记录。

原资料的竞品审计是只读观察。已看到表单、参数或按钮，不等于验证了真实生成、保存、权限、导出质量或后台模型。原型中的方案确认、错误恢复、任务状态、版本关系应标为我们设计的行为，不冒充竞品已经存在的运行事实。

## 3. 核心用户及用户任务

来源：XLSX「产品全景」R01–R05、J01–J05；DOCX「主要工作流与输入输出关系」。

| 使用者 | 真实任务 | 成功标准 | 对界面的要求 |
|---|---|---|---|
| 个人创作者 | 从一句需求、素材或模板开始做图文、多页作品 | 得到可再次修改的成品 | 入口直接、样例清晰、上下文持续保留 |
| 电商内容制作者 | 用同一商品资料制作主图、卖点、场景、详情与营销物料 | 主体一致、结构齐全、能单张返工 | 商品资料复用，图组结构清楚，批次与单张分开管理 |
| 内容与品牌设计者 | 产出海报、社媒套图、品牌视觉 | 信息准确、风格一致、适配发布规格 | 视觉参考与品牌规范可引用，尺寸和文案容易修改 |
| 办公与教学创作者 | 把文本、文件与数据变成 PPT、手册、绘本、信息图 | 内容结构完整、顺序正确、可编辑 | 大纲与版式分开、多页导航、清晰的格式边界 |
| 协作者或空间管理者 | 共享内容、品牌素材与移交资产 | 内容归属和访问范围清楚 | 属于扩展模块；资料只验证了介绍页，不能据此推导真实权限实现 |

建议以“电商视觉与营销内容创作”为首个完整演示场景，同时保留通用图片、海报、视频、PPT 等完整系统入口。电商套图同时覆盖复杂表单、素材引用、多结果、单张编辑和成套交付，最适合展示产品判断与界面能力。

## 5. 从能力地图转成用户可理解的信息架构

建议主导航使用以下入口，避免功能列表淹没创作工作区。

| 导航 | 用户问题 | 内容 |
|---|---|---|
| 创作首页 | 我今天想做什么？ | 自然语言输入、图片/视频模式、近期任务、高频场景与灵感 |
| 创作技能 | 我有明确任务，该怎么配置？ | 八类场景、搜索、推荐、配置面板、带入描述和生成 |
| 设计模板 | 我想从哪个版式开始？ | 模板筛选、预览、同款生成和直接编辑两条清晰路径 |
| AI 工具 | 我只想处理一个具体问题 | 抠图、去除、扩图、高清、翻译等专用工具 |
| 我的项目 | 我的作品在哪里？ | 项目、文件夹、作品、历史任务、筛选、最近打开 |
| 素材资产 | 哪些内容可以再次使用？ | 上传素材、创作参考、角色、品牌资料、收藏 |
| 任务中心 | 进展怎样、哪里需要处理？ | 排队、处理中、部分成功、完成、失败、取消及重试 |

工作台采用“明确任务后进入专用界面”的策略。生成工作台与画布编辑器是同一条流程里的不同阶段：前者组织输入和结果，后者精细编辑作品。无需在生成阶段暴露完整的图层和排版属性。

## 6. 建议的主闭环与设计顺序

### 首条完整闭环：商品资料 → 六张视觉物料 → 单张编辑 → 成套交付

1. 从首页选择“商品套图”，或输入“为新款植物精华做一组上新物料”。
2. 配置商品图、商品名称、已知卖点、平台、语言、比例；素材支持预览和删除。关键资料可自动带入但需可修改。
3. 选择“主图、卖点、场景、细节”等结构，实时显示总张数与成套预览。该步骤是我们设计的方案确认，不声称竞品已验证。
4. 提交后进入可追踪任务，显示当前阶段、结果数量与取消入口；保留原始资料。
5. 结果按用途归组，可多选、预览、收藏、只重做一张、继续描述调整。
6. 选一张进入画布，修改主标题、文案、背景色、图层位置和素材，支持撤销与缩放。
7. 导出时确认格式、尺寸、页面范围；回到项目可重新打开保存的版本。

### 从点到面的覆盖层次

| 层次 | 优先设计内容 | 原型表现要求 |
|---|---|---|
| P0：深度闭环 | 首页、技能配置、商品套图工作台、结果、编辑器、导出、项目续作 | 整条链可点击，关键字段真实变更，状态转换和保存有一致反馈 |
| P1：横向复用 | 模板中心、通用图片生成、AI 工具、素材资产、批量任务 | 复用同一交互规则；搜索筛选、选择和带入下游可操作 |
| P2：系统全貌 | 视频、PPT、多页内容、服饰、品牌、分享与品牌规范 | 提供领域特有配置和合理示例，清楚呈现与共用工作台的关系 |
| 暂不承担真实服务 | 模型调用、云同步、真实多人权限、真实支付 | 原型演示数据与真实执行分开；不将静态结果宣称为真实生成 |

这里的 P0/P1/P2 是本次设计先后顺序，不是替用户锁定开发版本范围。

## 7. 高保真原型必须表现的关键状态

来源：XLSX「功能说明」中的“目标草案与验收”。以下状态是原型设计建议，原资料并未端到端验证竞品行为。

| 环节 | 关键状态 | 设计细节 |
|---|---|---|
| 首页输入 | 空白、有输入、附素材、带技能、模式切换 | 空白时有真实示例；输入后主按钮明确；模式切换保留可复用内容 |
| 上传 | 拖入、处理中、成功、格式不支持、数量超限 | 文件错误与其他有效素材隔离；缩略图可预览/移除；限制属于当前入口 |
| 配置 | 默认、已修改、缺必填、参数冲突 | 立即显示输入错误；输出规格摘要与配置一致；高级选项逐步展示 |
| 提交 | 可提交、校验中、已提交 | 防重复点击；确认产物类型、数量、规格及项目归属 |
| 执行 | 等待、处理中、部分成功、完成、失败、取消 | 长任务能离开页面；批量成功和失败分开；重试只处理失败项 |
| 结果 | 默认、多选、收藏、预览、单张续作、全部选择 | 新结果不覆盖原结果；保留输入与参数来源；选中计数明确 |
| 编辑 | 未选中、单选、多选、文本编辑、拖动、属性修改 | 属性面板对应当前对象；撤销重做；缩放与实际输出尺寸分开 |
| 保存 | 有改动、保存中、已保存、保存失败、副本 | 对于本地原型可用浏览器保存；不能以“云端已同步”伪称真实后端 |
| 导出 | 参数、处理中、成功、失败重试 | 格式、透明背景与页面范围相容；无法真正生成的格式不能伪下载 |
| 项目 | 有内容、空项目、搜索无结果、筛选、多选 | 空态提供新建或重置筛选动作；项目和任务之间能互相定位 |
| 分享 | 仅自己、已启用、权限修改、撤销 | 若仅为原型，应标明演示；不要创建真实公开链接冒充效果 |

资料里同一任务的入口约束会不同。例如商品套图工具最多 6 张、Skill 最多 10 张；图片批处理工具 30 张、批量修图 Skill 20 张。来源：DOCX「输入限制应属于具体入口」。原型应定义自己明确的一套入口规则，不能混贴数字。

## 8. 视觉和交互着力点

1. **让作品成为主视觉。** 创作产品的信心来自高质量的图文案例、整组内容和可编辑预览，不依赖大面积宣传文案。
2. **保持稳定的工作框架。** 导航、全局搜索和项目归属稳定；任务相关的参数在局部变化，避免每个工具形成不同体系。
3. **把专业参数放在正确时机。** 首页轻量，配置清楚，编辑器密度更高；默认只显示会影响结果的重要选择。
4. **结果可比较、可选择、可继续。** 套组缩略图、用途标签、选中态和单张重做，比单独一张大图更能表达产品价值。
5. **为文字与图片各保留编辑路径。** 海报需要可读文字和布局控制；生成图作为图像素材，不能伪装成完全分层文档。
6. **状态有明确语言。** “已保存”“3/6 张完成”“请补充商品图”“重新生成这一张”都应指向具体对象和下一步。
7. **将范围差异放到文档。** 产品页面不塞实现说明和研究证据；原型状态仅在合适位置标注演示，开发说明在交付文档中给出。

## 9. 开发交接时需要明确的对象关系

来源：XLSX「产品全景」O01–O10。

创作需求引用输入素材、商品/品牌/角色资料和场景配方，生成任务产生多个候选结果；选定结果可作为设计文档内的图片，也可被下一轮任务引用。设计文档包含页面及元素，归属于项目；导出文件是文档的交付副产物，不等于可编辑源文档。

这一对象关系决定几个关键规则：原素材不被处理结果覆盖；任务结果和编辑版本分开；模板生成个人副本；单张续作不改变整组其他结果；导出行为不丢弃可编辑源稿。

## 10. 目前资料不能证明的内容

不能依据这两份材料声称已验证实际模型版本、实时数据接入、生成质量、主体一致性、失败恢复、云端存储、最终文件格式、导出透明度、真实分享权限或团队后台。模型菜单的 13 项图像标签和 23 项视频标签只证明 UI 选项可见，不是拟建平台的接入清单。

真实开发阶段再决定模型与服务、数据保留、质量标准、批量规模、取消时机、团队范围和产物格式；原型阶段则应先把这些决策在界面上将如何影响用户表现清楚。
